# Security Policy

## Supported branch

- `main`

## Reporting a vulnerability

- Do not open a public issue for security vulnerabilities.
- Use GitHub private vulnerability reporting for this repository if it is enabled.
- If private reporting is unavailable, contact the maintainers through GitHub without publishing exploit details.

## Reporting expectations

- Include the affected area, impact, reproduction steps, and any known mitigations.
- Keep reports focused, factual, and reproducible.
- Avoid sharing secrets, tokens, production credentials, or private customer data.

## Repository posture

- This repository is in active Phase 0 hardening.
- Treat current code as development-stage infrastructure, not audited production software.
